  1. This function generates an n x k dataset with all its entries drawn from a Poission distribution with mean lambda.
fun1 <- function(n = 100, k = 4, lambda = 4) {
  x <- NULL
  
  for (i in 1:n){
    x <- rbind(x, rpois(k, lambda))    
  }
  
  return(x)
}

fun1alt <- function(n = 100, k = 4, lambda = 4) {
# Generate all n*k draws at once, then format as an n x k matrix
  matrix(rpois(n * k, lambda), nrow = n, ncol = k, byrow = TRUE)
}

Problem 2: Parallelization

We will now turn our attention to the statistical concept of bootstrapping. Among its many uses, non-parametric bootstrapping allows us to obtain confidence intervals for parameter estimates without relying on parametric assumptions. Don’t worry if these concepts are unfamiliar, we only care about the computation methods in this lab, not the statistics.

The main assumption is that we can approximate the results of many repeated experiments by resampling observations from our original dataset, which reflects the population.

  1. This function implements a serial version of the bootstrap. Edit this function to parallelize the lapply loop, using whichever method you prefer. Rather than specifying the number of cores to use, use the number given by the ncpus argument, so that we can test it with different numbers of cores later.
my_boot <- function(dat, stat, R, ncpus = 1L) {
  
  # Getting the random indices
  n <- nrow(dat)
  idx <- matrix(sample.int(n, n * R, TRUE), nrow = n, ncol = R)
  
  if (ncpus > 1L) {
    # 1. Create a background cluster with the specified number of cores
    cl <- makeCluster(ncpus)
    
    # 2. Export necessary variables and functions to the cluster workers
    clusterExport(cl, varlist = c("dat", "idx", "stat"), envir = environment())
    
    # 3. Run the parallelized loop
    ans <- parLapply(cl, seq_len(R), function(i) {
      stat(dat[idx[, i], , drop = FALSE])
    })
    
    # 4. Shut down the cluster to free up memory
    stopCluster(cl) 
    
  } else {
    # If ncpus is 1, just run the standard, serial lapply
    ans <- lapply(seq_len(R), function(i) {
      stat(dat[idx[, i], , drop = FALSE])
    })
  }
  
  # Converting the list into a matrix
  ans <- do.call(rbind, ans)
  return(ans)
}

  1. Explain in your own words how you can decide if a problem is fit for parallelization?

Ans: I think two points to consider, 1) task dependence, If I have computations A and B, A and B can be done independently and have same results, then parallelization can be considered; 2) cost from coputational loading, if the heavy computational loading is costly, then we can consider parallelization to save the budget.

  1. We have covered vectorization and parallelization in this lab. Explain in your own words how you can think about the relationship between vectorization and paralleization? How do we know whether we should use one or the other or both?

Ans: Vectorization happens in a single CPU core, while paralleization happens in multiple CPU cores. We may consider vectorization first because it only requires a single CPU core. But if you still take much time in computation, then you may consider paralleization.
